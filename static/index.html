Arquitetura de Transmissão e Interoperabilidade SUS

Como os dados trafegam desde o atendimento clínico na UBS até a consolidação federal no SISAB e RNDS.

1. Unidade de Saúde (UBS)

Atendimento ao Cidadão

Médicos, enfermeiros, dentistas e agentes de saúde registram consultas, visitas domiciliares, procedimentos e vacinas.

Coleta: e-SUS PEC ou ERP Próprio
2. Barramentos em Tempo de Execução

Consulta CADSUS & RNDS

A recepção busca o paciente no SOA-CADSUS WSDL. Vacinas aplicadas geram pacotes HL7 FHIR para a RNDS.

Protocolos: SOAP / XML & FHIR R4
3. Centralizador Nacional

esusab.saude.gov.br

O PEC municipal gera arquivos binários Thrift (.esus/.zip) e envia periodicamente para o pool F5 / JBoss nacional.

Versão Atual: v5.7.36 (Porta 443)
4. Base Federal

SISAB & e-Gestor APS

Validação das fichas, apuração dos indicadores do cofinanciamento da APS (Portaria 3.493/2024) e cálculo de repasses.

Consolidação Quadrimestral
Por que monitorar a API separadamente da Interface Web?

Muitos serviços governamentais possuem arquiteturas desacopladas. O portal de operadores (como o cadastro.saude.gov.br/novocartao/) pode ficar sobrecarregado ou apresentar falhas no servidor de apresentação web enquanto o barramento de integração máquina-a-máquina (servicos.saude.gov.br/cadsus/.../v5r0?wsdl) continua respondendo normalmente.

Com este painel, os gestores e a equipe de TI da saúde identificam se um erro é apenas cosmético no navegador ou se de fato impede o atendimento e a transmissão de lotes.

Status SUS — Observabilidade Independente

Painel leve e autocontido para monitoramento de disponibilidade e tempo de resposta da infraestrutura digital de saúde pública brasileira (DATASUS, Ministério da Saúde e Gov.br).

Características Principais:

  • Zero dependências pesadas: Backend em Python nativo com biblioteca padrão (http.server, urllib, ssl, socket, concurrent.futures).
  • Varredura Concorrente: Sonda todos os endpoints em paralelo em menos de 2 segundos.
  • Inspeção Heurística: Extrai a versão e data de build do Centralizador Nacional e-SUS e valida o contrato XML WSDL do CADSUS.
  • Totalmente Customizável: Suporte a arquivo config.json para inclusão opcional de servidores locais (instâncias próprias do e-SUS PEC, bancos de dados municipais ou portais estaduais).

Como Adicionar Endpoints Municipais / Estaduais

Para monitorar a instância local do e-SUS PEC ou o sistema da sua Secretaria de Saúde, basta editar o arquivo config.json na raiz do projeto: 

{
  "server": {
    "port": 8765,
    "host": "0.0.0.0"
  },
  "customEndpoints": [
    {
      "id": "pec-local",
      "name": "e-SUS PEC Local",
      "shortName": "PEC Local",
      "layer": "municipal_local",
      "layerLabel": "Instância Municipal",
      "protocol": "TCP / PostgreSQL",
      "type": "Banco de Dados",
      "url": "tcp://192.168.1.100:5433",
      "tcpHost": "192.168.1.100",
      "tcpPort": 5433,
      "expectedCodes": [200],
      "warnLatencyMs": 100,
      "enabled": true
    }
  ]
}
Qualquer alteração no config.json é carregada no próximo reinício do servidor.
